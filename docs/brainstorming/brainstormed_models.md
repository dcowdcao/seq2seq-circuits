# Brainstormed models and circuits

Candidate operators and models proposed for the model zoo, each with the circuit classes it is
expected to yield and the specific circuit rows (domain conditions, contrast edits, probe variables,
bridges, suppression tests) it was designed to support. This is a research brainstorm: the
predictions in the table are hypotheses written before the proposed model was trained, not results.
Many of the proposed models were later built and trained (an id that appears in
[results/zoo/models_index.csv](../../results/zoo/models_index.csv) has a checkpoint in the zoo
snapshot); the others have no checkpoint in this snapshot. Remarks in the rows about models that
already existed (their circuit sizes, failed circuits or probes, error rates) describe the zoo as it
stood when the batch was written; they motivated the proposals and are not results of this release,
whose zoo-wide statistics are in [results/zoo/stats.md](../../results/zoo/stats.md). The
operators that were built are documented in [../reference/operators.md](../reference/operators.md);
plain-language explanations of many proposed operators are in
[operator_glossary.md](operator_glossary.md); the overview of how operators are chosen is in
[../brainstorming.md](../brainstorming.md). Circuit classes are defined in
[../reference/circuit_types.md](../reference/circuit_types.md).

## How the proposals were generated

Proposals were sought along several directions, in successive batches:

- **Coverage of the circuit classes.** Each operator should yield circuits of at least one class
  (DomainCircuit, ContrastCircuit, ProbeCircuit, BridgeCircuit, SuppressionCircuit), with
  DomainCircuits and ContrastCircuits the most common and every batch also adding probe, bridge,
  suppression or mux material where the mechanism allows it.
- **Named algorithms and scientific computations.** Operators drawn from named algorithms and from
  physics, signal processing, number theory, group theory, cryptography, automata, compression and
  data structures (for example sandpile and rule-184 cellular automata, a Schmitt trigger, rail-fence
  transposition, dihedral and quaternion group products, Count-Min sketches), rather than
  permutations of an internal design grid.
- **Distinct mechanisms.** Later batches prioritized mechanisms far from every existing operator
  (bit-level operations, comparison topologies, bounded machines, new algebras such as max-plus
  scans).
- **Plain semantics.** A mild preference for operators whose behaviour fits one sentence.
- **Trainability.** Every operator must be learnable by the toy transformers; mechanisms that need
  unbounded pointer chasing or deep dynamic programming were recast into a bounded form or dropped.

Each operator was checked against a Python reference implementation; the examples in the table are
computed from it.

## Column legend

- **batch**: the proposal batch (`Wn` in the text refers to batch n).
- **kind**: `op` = a new operator (one model); `op-family` = a set of operators sharing a rule with
  a tunable knob; `mux` / `mux-family` = a multiplexed model (a leading cue token selects one of N
  member tasks); `composition` = a composite model A(B(x)); `ZT-*` = zero-training experiments that
  run on already-trained checkpoints (`ZT-domain`, `ZT-contrast`, `ZT-probe`, `ZT-probe-circuit`,
  `ZT-suppression`, `ZT-instrument`, `ZT-measurement`, `ZT-analysis`); `protocol` = an analysis
  recipe across several models; `diagnosis` = an audit of the analysis method; `condition-class` = a
  new kind of input condition.
- **expected circuit classes**: Domain = DomainCircuit, Contrast = ContrastCircuit, Probe =
  ProbeCircuit, Bridge = BridgeCircuit, Suppression = SuppressionCircuit, mux = breadth / routing
  material from a multiplexed model; the first listed is the primary one. `—` for pure
  measurement rows.
- **algorithm** and **example**: what the operator does, and one input → output row (digit strings,
  position 0 leftmost; mux examples show `[cue]payload` for one member).
- **circuits (key rows)**: the circuit rows the proposal is designed to produce, with predictions.
- **status** (set when the row was written and not updated since): `queued` = a proposal queued
  for building (whether it was built is recorded by the zoo index, not by this column);
  `ZT` = a zero-training analysis of existing checkpoints (no results for these rows are included);
  `cont` = a protocol contingent on other entries being built.

Vocabulary used in the circuits column:

- **domain**: an input slice on which the task provably simplifies; circuit search runs there.
- **contrast**: clean/corrupt input pairs; the **mask** = positions where the true output differs.
  Mask shapes: **singleton** (one position), **window** (a contiguous run), **suffix** (from the edit
  to the end), **sparse** (scattered, non-adjacent positions), **alternating** (every other
  position), **perforated / porous** (a suffix or run with holes), **empty** (provably no change: an
  invariance control).
- **probe**: a linear readout of a hidden quantity from the residual stream; **eager** = the model
  computes and keeps it along the way, **lazy** = it is only reconstructed at the readout; **cf** =
  the input edit that changes that quantity coherently (needed for the causal test).
- **bridge**: for a two-step task A(B(x)), the intermediate value B(x), never printed, possibly
  represented internally.
- **suppression / release**: a computation that runs regardless and must be actively cancelled;
  release = cut the cancelling edges and see the suppressed answer leak out. **census / neg-mass** =
  how much negative-scored edge weight a circuit carries.
- **mux / cue / router / outvoting**: the first token is a command symbol picking which of N tasks
  runs; the router reads it; outvoting = a wrong task computes anyway and is silenced at the output.
- **winner: tiny / medium / near-full**: the size bucket of the selected smallest faithful circuit.
- **__mlp / __moe / __deep / __wide / __xl**: architecture variants (add an MLP block / add a
  mixture-of-experts block with a learned per-token router / 8 layers / 16 heads / 8 layers × 16
  heads); `__nope` (no positional embeddings) was an early variant that is no longer built.
  **nope-viable** / **nope-FATAL** (also *__nope viable / fatal / flagship*): the prediction that
  the operator would / would not still train without positional embeddings.
- **dom / con / sup**: domain / contrast / suppression rows.
- **causal gate**: the probe's causal test in
  [pipeline/probes/validate_probe.py](../../pipeline/probes/validate_probe.py): *steer* = the
  probe moves, *flip* (*flip-real*) = the model's output moves at the toggled slot; *defined* = the
  share of rows on which the variable's cf exists. A *PASS shot* is a variable designed to give that
  test a good chance of passing; a *STEER* read is used for a variable consumed only later, on which
  the output test is vacuous.
- **fdl**: first decodable layer of a probe variable.
- **registered**: a prediction written down before the model is built.
- **cell** (e.g. `global/redundant/winner`, `hidden_state/decodable_and_used`): a combination of
  row properties the proposals aimed to cover; *empty* / *thin* (THIN) = no or few rows with that
  combination existed when the batch was written.
- Counts such as `512/512` are checks of the reference implementation on sampled rows, not
  measurements of trained models.
